Sobol sensitivity analysis ​

A global sensitivity analysis tells which input parameters drive the variation of a simulated quantity when the parameters are uncertain. BattMo computes variance-based Sobol indices [12] of scalar quantities of a simulation, such as the delivered energy or the generated heat, with respect to scalar cell parameters. Unlike a local sensitivity (a derivative at one point), Sobol indices account for the full range of each parameter and for interactions between parameters.

The workflow follows the calibration API: create a SobolSensitivity from a Simulation, free the parameters to vary, and call solve. Two estimation methods are available:

  • :saltelli (default): Monte Carlo estimators on the Saltelli sampling scheme [13]. They make no assumption on how the quantities depend on the parameters, but need many simulations.

  • :pce: a polynomial chaos expansion (PCE) [14], a polynomial surrogate of the quantities fitted to the simulations, from which the indices follow analytically. It needs far fewer simulations when the quantities depend smoothly on the parameters.

A complete, runnable study that compares both methods is given in the Sobol sensitivity example.

  • A parameter with a small has no influence on the quantity within its bounds and can be fixed at its nominal value, for example before a calibration.

  • A large gap   means that the effect of the parameter depends on the values of other parameters.

  • If is close to one, the quantity is close to additive in the parameters.

The indices depend on the chosen bounds. Widening the range of one parameter increases its share of the variance at the expense of the others, so the bounds should reflect the actual uncertainty of each parameter.

Usage ​

Setting up the analysis ​

julia
using BattMo

cell_parameters = load_cell_parameters(; from_default_set = "chen_2020")
cycling_protocol = load_cycling_protocol(; from_default_set = "cc_discharge")
model = LithiumIonBattery()
sim = Simulation(model, cell_parameters, cycling_protocol)

sa = SobolSensitivity(sim)

SobolSensitivity stores a deep copy of the simulation, so the original sim can be reused.

Selecting parameters ​

A parameter is identified by its path in the cell parameters, as for calibration. Each free parameter needs a lower and an upper bound, and its nominal value in the cell parameters must lie within them:

julia
free_sensitivity_parameter!(sa, ["NegativeElectrode", "ActiveMaterial", "DiffusionCoefficient"];
    lower_bound = 1e-14, upper_bound = 1e-13, scaling = :log)
free_sensitivity_parameter!(sa, ["Electrolyte", "BruggemanCoefficient"];
    lower_bound = 1.3, upper_bound = 2.0)

Parameters are sampled independently and uniformly between their bounds:

  • scaling = :linear (default) samples uniformly in .

  • scaling = :log samples uniformly, which suits parameters that span several orders of magnitude, such as diffusion coefficients and reaction rate constants. The lower bound must be positive.

Only scalar parameters can be varied. Functional parameters, such as an OCP or a concentration-dependent conductivity given as a function or table, cannot be selected. A parameter is removed again with freeze_sensitivity_parameter!, and print_sensitivity_overview prints the free parameters, their bounds and scaling, and the quantities.

Selecting quantities ​

sa.quantities is a dictionary from a name to a function f(output::SimulationOutput) -> Float64. The defaults, from default_sobol_quantities, are:

NameDefinitionUnit
EnergyEnergy throughput   Wh
PowerEnergy throughput divided by the time with nonzero currentW
HeatGenerated irreversible heat, see Heat generationWh

These definitions assume a single charge or discharge. For a cycling protocol, or for any other quantity, add or replace entries:

julia
sa.quantities["PeakHeatRate"] = output -> maximum(compute_heat_generation(output).rate)
sa.quantities["Capacity"] = output -> output.metrics["DischargeCapacity"][end]
delete!(sa.quantities, "Power")

A quantity function that throws an error gives NaN for that sample, which is treated as a failed sample (see below).

Running the analysis ​

julia
result = solve(sa; N = 64)                         # Saltelli, 64 * (d + 2) simulations
result_pce = solve(sa; method = :pce, degree = 3)  # PCE, 2 * binomial(d + 3, 3) simulations
print_sensitivity_overview(sa)

Integral quantities of a charge or discharge, such as the energy or the generated heat, usually depend smoothly on transport and kinetic parameters within moderate bounds, and the PCE then reaches a given accuracy with far fewer simulations. The Saltelli scheme is the safer choice for quantities with kinks or jumps, and as a reference to verify a PCE. Typical non-smooth quantities are maxima over time, such as a peak heat generation rate (the time of the peak can jump from one part of the discharge to another), and quantities of discharges that end erratically, for example when strong electrolyte depletion makes the end of the discharge sensitive to small parameter changes. Note that such behaviour also affects the Saltelli estimates, which then attribute variance to the parameters that is caused by the non-smooth response; plotting the samples (see the example) helps to spot it. A low (a warning is printed below 0.9) shows that the polynomial does not represent the quantity well, and that the PCE indices should not be trusted.

The PCE needs coefficients, which grows quickly with the number of parameters and the degree: 56 for   , 286 for    and 1771 for   . For many parameters, use a low degree or screen out unimportant parameters first.

Implementation ​

Both methods sample the parameters in the unit cube . Each point is mapped to physical parameter values according to the bounds and scaling of each parameter, the values are written into a copy of the cell parameters, and a new simulation is set up and solved with logging switched off. The cost is dominated by the simulations; the estimators themselves take a negligible time.

Quasi-random sampling ​

By default, and are uniform random samples. Quasi-random (low-discrepancy) sequences usually converge faster. They can be used through the sampler keyword, a function (N, d, rng) -> (A, B) that returns two   matrices with values in . A common choice is to draw points of a -dimensional Sobol sequence and split the columns, for example with the Sobol.jl package:

julia
using Sobol

function sobol_sampler(N, d, rng)
    s = SobolSeq(2d)
    X = reduce(vcat, (next!(s)' for _ in 1:N))
    return X[:, 1:d], X[:, (d + 1):end]
end

result = solve(sa; N = 64, sampler = sobol_sampler)

Use a power of two for N with Sobol sequences. With method = :pce, the sampler is called in the same way and only is used.

Confidence intervals. The intervals are computed with a residual bootstrap: the residuals of the fit, scaled by and centred, are resampled with replacement and added to the fitted values, the PCE is refitted to these values bootstrap times (reusing the QR factorisation), and the interval is given by the empirical quantiles of the indices. The intervals thus reflect how the misfit of the PCE propagates into the indices. Resampling the points themselves, as for the Saltelli scheme, is not used: a resample contains only about 63% distinct points, so with   every refit overfits and the intervals of small indices are biased upwards. The residual bootstrap does not capture the bias from truncating the expansion at degree , so the intervals are too narrow when the truncation error is not negligible. In a test on the Ishigami function with  , the 95% intervals of the total-order indices contained the exact values in 75–90% of the repetitions for  -, while the point resampling scheme gave intervals three to five times wider that missed the smallest index in most repetitions. The fitted expansion is stored in result.pce as (degree, multi_indices, coefficients, q2), with the multi-indices as rows of multi_indices and one column of coefficients per quantity.

Failed simulations ​

Some parameter combinations can make a simulation fail, for example when the solver does not converge or the cell reaches a cut-off immediately. A failed simulation returns NaN for every quantity, and a quantity function that throws returns NaN for that quantity. A warning reports the number of failed simulations.

With the Saltelli scheme, the estimators combine values from the same row of , and every , so a base sample is dropped for a quantity when any of its   values is not finite. With the PCE, only the failed simulation itself is dropped from the fit. The number of samples used is reported per quantity in result.n_valid and in the printed table. If many samples fail, the remaining samples no longer cover the parameter space uniformly and the indices are biased; narrowing the bounds or adjusting the solver settings is then preferable. If too few samples remain (fewer than two base samples for :saltelli, at most for :pce) or a quantity has zero variance, its indices are NaN.

Parallel execution ​

With parallel = true (the default when Julia runs with several threads), the simulations are split into one chunk per thread. Each chunk works on its own copy of the model, since setting up a simulation modifies the model. Jutul's internal (Polyester) threading of the assembly is not safe to use from several tasks at once, so it is switched off while the simulations run in parallel; each simulation then runs on a single thread. Start Julia with julia -t auto to use all cores. The speed-up is usually lower than the number of threads; measure it on your machine for large studies.

Heat generation ​

The Heat quantity is computed with compute_heat_generation, which returns the time series of the irreversible heat generation rate in W and its time integral in J. Reversible (entropic) heat is not included. Two methods are available:

  • :bernardi (default) uses the energy balance of Bernardi et al. [17],

where is the difference of the positive and negative electrode open-circuit potentials, evaluated at the volume-averaged particle concentration of each electrode. This is the total dissipated energy, including the energy stored in concentration gradients, which is released as heat when the cell relaxes. It is cheap and works for every geometry.

  • :source_terms sums the ohmic, electrolyte diffusion and irreversible reaction heat sources of the BattMo thermal model over the domain. Energy stored in concentration gradients inside the particles is not included. This method evaluates all secondary variables at every report step and is much slower than the simulation itself.

The method used by the default quantities is chosen with default_sobol_quantities(; heat_method = :source_terms). The time integrals use the trapezoidal rule over the report steps, with the rate at the first report step used for the first interval from time zero.

Working with the result ​

A SobolResult holds:

  • parameter_names and quantity_names, sorted alphabetically. Parameter paths are joined with ..

  • first_order and total_order: matrices with one row per parameter and one column per quantity.

  • first_order_ci and total_order_ci: (lower, upper) matrices of the same size, or nothing when bootstrap = 0.

  • samples and values: the physical parameter values and the quantity values of all simulations, one row per simulation.

  • N and n_valid.

  • method: :saltelli or :pce.

  • pce: the fitted expansion and its for :pce, otherwise nothing.

print_sobol_indices prints one table per quantity, sorted by total-order index. The stored samples can be reused without new simulations, for example for scatter plots of each quantity against each parameter, which show how a parameter acts where the indices show how much. The example plots the indices, compares the two methods, and shows the scatter plots.

Limitations ​

  • Parameters are assumed independent and uniformly distributed (in linear or log10 space). Correlated parameters or other distributions are not supported.

  • Only scalar cell parameters can be varied; cycling protocol and simulation settings are fixed.

  • Only first- and total-order indices are computed; second-order interaction indices are not.

  • The PCE uses a full total-degree basis. Sparse or adaptive bases, which scale better to many parameters, are not implemented.

  • The default quantities assume a single charge or discharge.
